《人工智能基础》大作业开题报告 

**选题一：AI Agent框架搭建——从“会说话”到“能做事”** 

一、技术背景调研与文献分析 

1.1 技术现状 

自2023年以来，大语言模型（LLM）快速发展，人工智能应用正从传统聊天机器人向具备自主决策与工具调用能力的AI Agent演进 。AI Agent能够结合外部工具、知识库及环境信息完成复杂任务，是当前大模型应用层最重要的发展方向之一 。

* 
**(1) ReAct（Reasoning + Acting）范式** ReAct由Google与Princeton University提出，其核心思想是让模型在“推理（Thought）”与“行动（Action）”之间交替执行 。模型首先分析任务需求，再选择合适工具完成操作，并根据执行结果继续推理，最终给出答案 。ReAct无需依赖模型原生函数调用能力，仅通过Prompt工程即可实现，是当前轻量级Agent开发的重要方案 。


* 
**(2) Function Calling函数调用** OpenAI、DeepSeek、通义千问等主流模型均支持Function Calling机制 。模型按照预定义JSON格式输出工具名称和参数，由程序自动完成调用 。相比ReAct，其解析更加稳定，但推理过程不透明，对底层原理学习帮助有限 。
**ReAct与Function Calling对比：** 


* ① ReAct通过Prompt控制输出流程，可解释性强； 


* ② Function Calling依赖模型原生接口，实现简单但灵活性较低； 


* ③ ReAct能够完整展示Agent思考过程，更符合本课程“从零实现Agent框架”的教学目标 。




* 
**(3) 多Agent协作范式** 复杂Agent系统通常由规划Agent、执行Agent和反思Agent共同协作完成任务 。多Agent具有更强的任务拆解与协同能力，但系统复杂度较高 。本项目首先实现单Agent架构，并预留向多Agent扩展的接口 。


* 
**(4) 主流工具能力与框架生态** 当前Agent系统普遍具备计算器、搜索引擎、本地文件管理、天气查询等工具能力 。课程要求至少实现三个工具，因此本项目计划实现计算器、Wikipedia搜索以及本地文件读写功能 。LangChain、LlamaIndex等框架已封装完整Agent能力，但为了深入理解Agent运行机制，本项目不采用高层框架，而是基于Python与LLM API自主实现Agent执行闭环 。



1.2 核心原理预研 

* 
**(1) Agent通过Prompt约束模型输出** 项目采用ReAct范式，通过系统提示词（System Prompt）对模型输出进行严格规范 。提示词中预定义工具列表、参数格式、执行规则以及终止条件，引导模型按照“Thought→Action→Observation→Final Answer”的结构进行输出，从而保证输出内容能够被程序稳定解析 。


* 
**(2) ReAct执行闭环机制** 系统整体执行流程如下：用户请求 → 构建Prompt → LLM生成Thought与Action → 解析Action → 调用工具 → 获取Observation → 更新上下文 → 继续推理 → 输出最终答案 。该闭环机制使Agent能够根据执行结果动态调整后续行为，实现多步推理和复杂任务求解 。


* 
**(3) 解析与执行循环** 系统设计专门的输出解析模块，对模型生成内容进行结构化提取，识别工具名称和参数信息；随后通过工具路由模块调用对应函数，并将执行结果作为Observation重新加入上下文 。当模型输出Final Answer或达到最大循环次数时结束执行 。


* 
**(4) 对话历史与短期记忆管理** 项目使用messages列表维护完整会话历史，并采用上下文窗口裁剪策略控制Token长度，仅保留最近若干轮关键交互信息，保证多轮任务的稳定运行 。同时预留短期记忆扩展接口，为后续实现记忆功能提供支持 。
